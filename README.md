# Свадебный сайт — шаблон для перепродажи

Next.js + Supabase + Vercel. Один репозиторий = один шаблон.
Под каждую новую пару — отдельный форк/копия, отдельный проект
Supabase, отдельный деплой на Vercel.

## Что внутри

- Одностраничный сайт: имена, обратный отсчёт, история знакомства,
  программа, место + карта, дресс-код, RSVP-форма, гостиницы,
  транспорт, галерея, подарки, контакты.
- `/admin` — простая CMS: пара сама редактирует тексты, фото,
  видит список RSVP-ответов, может выгрузить их в CSV, может
  переключить визуальную тему.
- 3 готовые темы оформления (Классика / Минимализм / Природа) —
  переключаются в админке без правки кода.

## Стек и почему именно он

| Задача | Инструмент | Почему |
|---|---|---|
| Фронтенд + админка | Next.js (App Router) | Один код для публичных страниц и защищённой админки |
| База данных, авторизация, файлы | Supabase | Postgres + Auth + Storage в одном бесплатном проекте на клиента |
| Хостинг | Vercel | Деплой из GitHub одной кнопкой, бесплатного тарифа хватает с запасом |

Каждая новая пара = отдельный бесплатный проект Supabase
(лимитов бесплатного тарифа с большим запасом хватает на
RSVP и фото одной свадьбы) + отдельный бесплатный проект
Vercel. Твои затраты на инфраструктуру на одного клиента — 0 ₽,
пока не понадобится кастомный домен (это уже покупает клиент
сам, отдельно).

## Важное ограничение

Я собрал весь код и структуру проекта, но **не могу сам создать
Supabase-проект или задеплоить на Vercel** — у среды, в которой я
работаю, нет доступа в интернет. Дальше — твои шаги.

## Настройка нового сайта под конкретную пару (делать при каждой продаже)

### 1. Скопировать репозиторий
Через GitHub: кнопка **Use this template** (если репозиторий
сохранён как template-репо) или просто `git clone`, затем
`git remote set-url origin <новый-репозиторий-пары>`.

### 2. Создать проект Supabase
1. [supabase.com](https://supabase.com) → **New project**.
2. **SQL Editor** → вставить содержимое `supabase/schema.sql` целиком → **Run**.
   Это создаст все таблицы, политики безопасности и bucket для фото.
3. **Authentication → Users → Add user** — создать один аккаунт
   (email + пароль) для пары. Это их логин в `/admin`.
4. **Project Settings → API** — скопировать `Project URL` и `anon public key`.

### 3. Настроить переменные окружения
Скопировать `.env.example` → `.env.local`, вставить значения из шага 2.4.

### 4. Проверить локально
```bash
npm install
npm run dev
```
Открыть `http://localhost:3000` — сайт с данными по умолчанию.
Открыть `http://localhost:3000/admin` — войти под созданным логином,
заполнить реальные данные пары.

### 5. Задеплоить на Vercel
1. [vercel.com](https://vercel.com) → **New Project** → выбрать
   репозиторий пары.
2. В **Environment Variables** добавить те же переменные, что в `.env.local`.
3. Deploy. Vercel выдаст ссылку вида `имя-проекта.vercel.app` —
   это и есть личная ссылка пары. Можно подключить свой домен
   в Project Settings → Domains.

### 6. Передать паре
Отдать: ссылку на сайт, ссылку на `/admin`, email и пароль от админки.

## Смена темы

Тема переключается парой самостоятельно в `/admin/theme` —
хранится в поле `site_config.active_theme`, применяется мгновенно,
без деплоя. Если хочешь продавать сайт «с определённым стилем
из коробки» — просто заранее выставь нужную тему в этом же разделе
до передачи пары.

## Гостевые фото (опционально)

Отдельный блок «Ваши фотографии» — просто ссылка на папку, которую
пара создаёт сама (Google Диск, Google Фото, Яндекс.Диск — что угодно).
Никакой интеграции с API нет специально: так надёжнее и не ломается
от лимитов Google на хотлинкинг.

Настройка (делает пара сама, за минуту):
1. Создать папку в Google Диске.
2. **Доступ по ссылке → «Читатель» не подойдёт для загрузки чужих
   файлов** — нужно выбрать роль **«Редактор»**, иначе гости смогут
   только смотреть, но не добавлять свои фото.
3. Скопировать ссылку → вставить в `/admin/content` в поле
   «Ссылка на папку для гостевых фото».

Если поле пустое — блок на сайте автоматически не показывается.

## Email-уведомления о новом RSVP (опционально)

Без настройки RSVP всё равно работает и сохраняется в базу — письмо
просто не отправится. Чтобы пара получала уведомление на почту сразу,
как гость ответил:

1. Зарегистрироваться на [resend.com](https://resend.com) (бесплатно,
   3000 писем/мес) → скопировать API-ключ.
2. В Vercel → Project Settings → Environment Variables добавить:
   `RESEND_API_KEY`, `RSVP_WEBHOOK_SECRET` (любая случайная строка —
   придумать самому), `RESEND_FROM_EMAIL` (можно оставить
   `onboarding@resend.dev` для теста, для боевой рассылки со своего
   домена нужно подтвердить домен в Resend).
3. В Supabase → Database → Webhooks → **Create a new hook**:
   - Table: `rsvp_responses`, Event: `Insert`
   - Type: HTTP Request, Method: POST
   - URL: `https://<домен-сайта>/api/notify-rsvp`
   - HTTP Headers: `x-webhook-secret` = то же значение, что в `RSVP_WEBHOOK_SECRET`
4. Убедиться, что в `/admin/content` заполнено поле «Контактный email» —
   письмо уходит именно на него.

## Известные ограничения этой версии (стоит знать заранее)

- **Карта** — встроена через OpenStreetMap (без API-ключа, без
  ограничений и оплаты). Если для конкретного клиента важнее
  Яндекс.Карты — это замена одного файла (`components/sections/Venue.tsx`),
  но потребует API-ключа Яндекса на каждый сайт.
- **Один язык (русский)**. Мультиязычность не реализована — если
  понадобится для гостей-иностранцев, это отдельная доработка.
- **Секретность ссылки**. Сайт публичный по своей ссылке — тот, у
  кого есть URL, может открыть страницу и отправить RSVP от
  чужого имени. Для большинства свадеб это приемлемо, но явно
  предупреди об этом пару, если для их случая это важно.
- **Один админ-логин на сайт**. Модель "один клиент = один
  Supabase-проект" не предполагает, что ты как продавец имеешь
  доступ ко всем сайтам сразу — у тебя нет единой панели
  "все мои клиенты". Если захочешь такую панель для себя —
  это уже похоже на Модель B (SaaS-платформу) из обсуждения,
  и её стоит проектировать отдельно, а не как надстройку.

## Структура проекта

```
app/
  page.tsx              — главная страница (публичная)
  layout.tsx             — шрифты + применение активной темы
  admin/                — защищённая CMS
components/
  sections/              — секции публичного сайта
lib/
  supabase/               — клиенты Supabase (браузер/сервер)
  themes.ts               — описание 3 тем
supabase/
  schema.sql              — вся схема БД одним файлом
```
